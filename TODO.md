## Needs manual verification: `redirect: "manual"` on a valid session

`src/db/notes/crud.ts` sends every request with `redirect: "manual"` so an
expired Cloudflare Access session is distinguishable from a dead network.
Verified against an expired session; not yet re-checked against a valid one.

Run in the DevTools console on https://markdown-notes.vktrz.workers.dev while
signed in:

```js
const r = await fetch('/api/notes', { redirect: 'manual' });
console.log(r.type, r.status, r.ok);   // expect: basic 200 true
console.log((await r.json()).length);  // expect: the note count
```

Anything other than `basic 200 true` means `redirect: "manual"` changed the
normal path, and `check()` in `crud.ts` will reject valid responses.

**The two states, as measured:**

Signed out, without `redirect: "manual"` — Access 302s to
`wandering-rain-53fc.cloudflareaccess.com`, the cross-origin redirect fails the
CORS check, and `fetch` rejects:

```
TypeError: Failed to fetch
```

Identical to the offline error, which is why the option exists.

Signed out, with `redirect: "manual"` — the redirect is not followed:

```
opaqueredirect 0
```

`check()` turns that into an `Error` named `SessionExpired`; `isSessionExpired()`
tests for it.

To reproduce the signed-out state: DevTools → Application → Cookies → delete
`CF_Authorization`. (Or Zero Trust → My Team → Users → Revoke session, or
shorten the Access application's Session Duration.)

## Known bugs

### Delete paths swallow every error

`src/pages/NoteList/NoteCard.tsx`: `onConfirm={() => deleteNote(note.id).then(onDeleted)}`
`src/pages/Note/Note.tsx`, `handleDelete`: `deleteNote(noteId).then(() => navigate("/"))`

`deleteNote` ends in `.then(check)`, and `check` throws on a non-ok status —
neither call site has a `.catch`. A rejected delete is an unhandled promise
rejection: the modal closes, the note stays, nothing is shown. This is the one
failure path `ReauthNotice` doesn't reach; it's as silent on a 500 as it is on
an expired session.

### DELETE of a missing row returns 204

`worker/index.ts`'s DELETE branch doesn't check `meta.changes`, so deleting an
already-deleted note reports success. Harmless today. Matters once the offline
outbox (see Backlog) replays a delete and needs to tell "done" from "never
existed."

### `worker-configuration.d.ts` is 17,296 committed lines

Generated by `wrangler types`. Gitignore it and add a `types` script. The
Cloudflare build runs rsbuild only (no `tsc`), so deploy doesn't need this
file — but local dev and any future CI typecheck do, so generate it there
instead of committing it.

### The notes schema is written four times

`migrations/0001_create_notes.sql`, `NoteRow` in `worker/index.ts`, `Note` in
`src/db/notes/types.ts`, and the four SQL strings in `worker/index.ts` that
enumerate columns (SELECT list, INSERT RETURNING, SELECT by id, UPDATE
RETURNING). Adding one column touches six sites. A `NOTE_COLUMNS` constant in
the worker collapses four of them.

## Shipped: save retry with backoff

`attemptSave` in `src/pages/Note/Note.tsx` retries a failed PUT up to 3 times
(500ms, 1.5s, 4s) before setting `saveState` to `error`. `isRetryable()` in
`src/db/notes/crud.ts` decides which failures qualify: a network error or a
5xx retries; a `SessionExpired` or 4xx doesn't, since neither succeeds on a
second try, and retrying a stale PUT against a note deleted from another tab
would resurrect it. `HttpError` carries the response status so `isRetryable`
can make that call without parsing the error message.

This covers a live tab hitting a flaky network or a Worker hiccup. It does not
cover a PUT that never gets the chance to retry — the `keepalive` PUT flushed
at tab close, and the >60KB note that falls back to a plain request teardown
cancels (both under Offline, in Backlog). Those need the edit to survive past
the tab closing, which a retry loop inside a mounted component can't do.

## Backlog

### `updatedAt` as a write precondition

The column exists; nothing reads it. Send the `updatedAt` the client loaded
with the PUT, change the statement to
`UPDATE notes SET ... WHERE id = ? AND updatedAt IS ?` (`IS`, not `=`: it's
NULL for a note that's never been saved), and return 409 when no row comes
back. A silent cross-device overwrite becomes "changed on another device."
The client then needs to take `updatedAt` from each PUT response, not only
the initial GET.

This is the real conflict case for a single user editing from multiple
devices, and it's worth having before an offline replay queue exists.

### Query library: `@tanstack/react-query`

5.102.8, measured at 10.2 kB gzip (esbuild, React external).

The draft-loss bug that would have justified this is already fixed; what's
left is ergonomic:

- `useNotes()` and `useNote(id)` are independent fetches with no shared
  cache — a save in `NoteView` doesn't update the list, which only catches up
  on the next `visibilitychange`.
- `invalidateQueries(["notes"])` replaces the `onDeleted` refetch prop
  threaded from `NoteList` into `NoteCard` — every future write site needs
  that same thread without it.
- `useFetchOnFocus` (~60 lines) becomes unnecessary.

Against: 10.2 kB for an ergonomic win alone, and `CLAUDE.md` records "no
query library" as the design — adopting one changes that line in the same
commit.

Worth it if Offline (below) happens, since the same library can carry the
persistence. `swr` 2.5.1 (6.3 kB) has the same cache/focus core but no write
queue.

### Offline

**The service worker is the gate, not the data layer.** `index.html` and the
JS bundles come from the Cloudflare assets binding — without a service
worker, an offline reload is a network error page and no data code runs.
Editing only works in a tab that's already open.

There's no first-party option: `@rsbuild/plugin-pwa` isn't published. The
candidates are the community `rsbuild-plugin-pwa` (2.10.0), or
`@serwist/webpack-plugin` (9.5.12) / `workbox-webpack-plugin` (7.4.1) through
`tools.rspack`. None have confirmed Rspack compatibility — check before
picking one.

**For writes, a dirty-draft map, not a mutation queue.** `save` is a 500ms
debounce with `flushOnUnmount`, so typing a paragraph offline produces a tick
per pause. TanStack's paused mutations replay in order, and `scope.id` only
serializes them — there's no collapse-by-key, so dozens of PUTs would replay
to reach text already held locally. The only offline write here is "note N's
text is now X," which is idempotent and last-write-wins, so it doesn't need
that ordering:

- `idb-keyval` 6.3.0 (0.5 kB gzip), with its own `createStore("notes",
  "outbox")` — not the default store, or an unrelated key becomes
  `updateNote(NaN, ...)`.
- `stash(id, text)` before the PUT, delete the key on success, `flush()` on
  mount and on the `online` event.
- `updateNote`'s signature stays the same, so no component changes beyond
  the stash/flush calls.

The retry backoff (Shipped, above) already covers a live tab hitting a
transient failure. What's still unfixed here: a `keepalive` PUT flushed as
the tab closes can't report failure or retry, and a note over the 60KB
`keepalive` cap (`src/db/notes/crud.ts`) falls back to a plain request that
teardown cancels. Both need the edit to survive the tab closing, which
nothing today does.

Once a draft store exists, `ReauthNotice` can reload automatically instead of
waiting for a button click.

If persistence goes through TanStack instead of `idb-keyval` directly, use
`@tanstack/query-async-storage-persister` over IndexedDB, not
`query-sync-storage-persister` — that one is localStorage, synchronous, and
capped near 5MB, and notes here already pass 60KB. Measured 12.2 kB gzip for
query + persist-client + async-persister + idb-keyval.
