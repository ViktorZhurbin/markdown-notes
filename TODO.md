## Cheap, verified

### Delete paths swallow every error

`src/pages/NoteList/NoteCard.tsx` — `onConfirm={() => deleteNote(note.id).then(onDeleted)}`
`src/pages/Note/Note.tsx` `handleDelete` — `deleteNote(noteId).then(() => navigate("/"))`

`deleteNote` ends in `.then(check)` and `check` throws on a non-ok status, so
neither has a `.catch`: the rejection is unhandled, the modal closes, the note
stays, nothing is shown. Silent on a 500 and on an expired session alike — the
one path `ReauthNotice` does not reach.

### The notes schema is written four times

`migrations/0001_create_notes.sql`, `NoteRow` in `worker/index.ts`, `Note` in

### DELETE of a missing row returns 204

`worker/index.ts` — the DELETE branch does not check `meta.changes`, so deleting
an already-deleted note looks successful. Harmless today; matters once an outbox
replays a delete and needs to tell "done" from "never existed".

## Worth doing: `updatedAt` as a write precondition

The column exists and nothing reads it. Send the `updatedAt` the client loaded
with the PUT, change the statement to
`UPDATE notes SET ... WHERE id = ? AND updatedAt IS ?` (`IS`, not `=` — it is
NULL for a note that has never been saved), and return 409 when no row comes
back. That turns a silent cross-device overwrite into "changed on another
device". The client must then take `updatedAt` from each PUT response, not only
from the initial GET.

This is the real conflict case for a single-user app, and it is worth having
before any offline replay exists.

## Gated on a decision: offline

**The service worker is the gate, not the data layer.** `index.html` and the JS
bundles come from the Cloudflare assets binding, so without one an offline
reload is a network error page and no data code runs at all. Editing works only
in a tab that is already open.

There is no first-party option: `@rsbuild/plugin-pwa` is not published. The
candidates are the community `rsbuild-plugin-pwa` (2.10.0), or
`@serwist/webpack-plugin` (9.5.12) / `workbox-webpack-plugin` (7.4.1) through
`tools.rspack`. Rspack compatibility is unverified for all three — check before
committing to one.

**For the writes, use a dirty-draft map, not a mutation queue.** `save` is a
500 ms debounce with `flushOnUnmount`, so typing a paragraph offline produces a
tick per pause. TanStack's paused mutations replay in order and `scope.id` only
serializes them — there is no collapse-by-key, so you would replay dozens of
PUTs to reach text you already hold locally.

The only offline write here is "note N's text is now X", which is idempotent and
last-write-wins:

- `idb-keyval` 6.3.0, 0.5 kB gzip, with its own `createStore("notes", "outbox")`
  — not the default store, or an unrelated key becomes `updateNote(NaN, ...)`.
- `stash(id, text)` before the PUT, delete the key on success, `flush()` on mount
  and on the `window` `online` event.
- `updateNote`'s signature does not change, so no component changes.

This also covers two existing holes: a `keepalive` PUT flushed as the tab closes
cannot report failure, and a note over the 60 kB `keepalive` cap
(`src/db/notes/crud.ts`) falls back to a normal request that teardown cancels.

Once a draft store exists, `ReauthNotice` can reload automatically instead of
waiting for a button.

If persistence is wanted through TanStack instead: use
`@tanstack/query-async-storage-persister` over IndexedDB, **not**
`query-sync-storage-persister` — that one is localStorage, synchronous and
capped near 5 MB, and notes here already pass 60 kB. Measured 12.2 kB gzip for
query + persist-client + async-persister + idb-keyval.
